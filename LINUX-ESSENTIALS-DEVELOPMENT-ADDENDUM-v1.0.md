# Linux Essentials Development Standard Addendum

**Version 1.0**

This document supplements, but does not replace, Hydra Academy Development Standard Version 1.2. The LPI Linux Essentials campaign inherits every existing Hydra Academy platform, question, originality, validation, browser-verification, and release requirement unless this addendum explicitly establishes a certification-specific rule.

## 1. Official Blueprint Source

- **Certification:** LPI Linux Essentials
- **Exam code:** 010-160
- **Blueprint version:** LPI Version 1.6
- **Official structure:** Five topics and 19 objectives
- **Official exam format:** 40 questions in 60 minutes
- **Official source:** [LPI Linux Essentials Exam 010 Objectives](https://www.lpi.org/our-certifications/exam-010-objectives/)

## 2. Campaign Structure

Worlds 1–5 map directly to official LPI Topics 1–5. The Objective Sweep contains 19 separate objective banks distributed by world as 4 / 4 / 3 / 4 / 4.

World 6 dynamically combines all 19 Objective Sweep banks and must not maintain an independent or duplicate question bank. World 7 contains four dedicated Captain banks. World 8 serves as the Exam Chamber, and the Final Dungeon leads to six separate Practice Exam selections.

## 3. Question Production

All question content must map to an official LPI objective. Question distribution must follow the official LPI objective weights; equal question totals must not be forced across topics when doing so would distort the blueprint.

Recognition questions belong in the Objective Sweep. Scenario-based, analytical, and integrated questions belong in Captain banks and Practice Exams. Every command, option, path, permission, shell behavior, and Linux term must be technically accurate within the context presented.

## 4. Practice Exams

Each Linux Essentials Practice Exam must contain exactly 40 questions. Its distribution must reflect the official LPI objective weights, and all 19 objectives must receive appropriate representation across the complete six-exam set.

Every Practice Exam must be independently authored. All originality, substantive-similarity, schema, difficulty, navigation, loader, and release requirements from Hydra Academy Development Standard Version 1.2 remain mandatory.

## 5. Intentional Empty-State Behavior

Before content production, an empty Linux Essentials bank must display:

> This Linux Essentials question bank is ready for content.

An intentionally empty bank must not appear as a loader error, missing file, or broken campaign state.

## 6. Validation Requirements

The Linux Essentials campaign retains every applicable validation requirement from Hydra Academy Development Standard Version 1.2, including:

- JSON validation
- JavaScript syntax validation
- Loader-path validation
- Navigation validation
- Browser-console verification
- Responsive desktop, tablet, and mobile testing
- Duplicate and substantive-similarity audits
- Final release snapshot and SHA-256 hash verification

## 7. Future Revisions

If LPI updates the exam code, objective structure, objective weighting, or exam format, this addendum must not be silently overwritten. A revised addendum version must be created, the official blueprint change must be documented, and all Objective Sweep, Captain, and Practice Exam distributions must be reassessed before production or migration proceeds.
